# ADDITIONAL DEVELOPMENT REQUIREMENTS

## Data Input Module + PDF Report Generation Module

Implement the following two modules as first-class modules of the **Concrete Delivery Operations Intelligence System**.

These modules must be fully integrated with the existing delivery database, dashboard, analytics, projects, fleet, alerts, and authentication system.

The application must have **one source of truth for delivery data**. Data entered through the Data Input Module must immediately become available to the dashboard, analytics, alerts, and PDF reporting modules.

---

# MODULE 1: DATA INPUT & DELIVERY RECORDING

## 1. Purpose

Build a professional **Data Input & Delivery Recording Module** that allows authorized plant staff to create, update, and manage concrete delivery records.

The module should represent the actual operational workflow of a ready-mix concrete delivery:

**Order → Scheduling → Batching/Loading → Departure → Transit → Site Arrival → Waiting → Unloading → Completion**

The objective is to capture enough information to determine:

* Whether the delivery was on time
* How late it was
* Where the delay occurred
* Why the delay occurred
* How long each operational stage took
* Which projects experience recurring delays
* Which trucks experience recurring operational issues
* Whether delays are concentrated at the plant, during transit, or at the customer site

Do not design this as a generic CRUD form. It should feel like a dedicated operational data-entry system for a concrete plant.

# 7. Automatic Delivery Status

Based on the entered information, automatically determine the delivery status.

Possible states:

* Scheduled
* Loading
* Ready
* Departed
* In Transit
* At Site
* Waiting
* Unloading
* Completed
* Delayed
* Cancelled

The status should update according to operational events.

For example:

If:

```text
Actual Departure exists
Site Arrival does not exist
```

status can become:

**In Transit**

If:

```text
Site Arrival exists
Unloading Start does not exist
```

status:

**Waiting**

If:

```text
Unloading Completed exists
```

status:

**Completed**

Allow authorized users to manually override status where necessary, but record the override in the audit log.

---

# 8. AUTOMATIC DELAY CALCULATION

This is a core feature.

Calculate:

```text
Delivery Delay =
Actual Delivery Time - Estimated Delivery Time
```

Example:

```text
Estimated Delivery: 10:30 AM
Actual Delivery:    10:52 AM

Delivery Delay:     +22 minutes
```

Display the result prominently.

Example:

**22 min late**

If the delivery arrives early:

**8 min early**

If exactly on time:

**On time**

Do not display negative delays confusingly.

Convert the underlying calculation into a human-readable operational status.
